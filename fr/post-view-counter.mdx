## Vue d'ensemble

Le site web personnel embarque un petit ensemble de composants et de hooks pour suivre et afficher combien de fois les articles ont été lus :

- **`ViewCounter`** — affiche le nombre de lectures d'un article unique, alimenté par le hook `useViewCount`.
- **`SiteViews`** — affiche le nombre total de lectures sur l'ensemble des articles, alimenté par le hook `useTotalViews`.
- **`PostMeta`** — la signature combinée présentée sous le titre d'un article (date, temps de lecture estimé, nombre de vues).

Les trois s'appuient sur un service de vues partagé à l'adresse `https://api.paaatrrrick.com/views`. Le service renvoie des données tolérantes aux `null`, chaque composant n'affiche donc rien tant que l'appel réseau est en cours ou si la requête échoue.

## Quand utiliser chaque élément

| Component / hook         | Use when…                                                                       |
| ------------------------ | ------------------------------------------------------------------------------- |
| `ViewCounter` / `useViewCount` | You want a single post's read count, and you want the visit to be recorded.    |
| `SiteViews` / `useTotalViews`  | You want the total-reads number across the whole site (e.g. footer, about page). |
| `PostMeta`               | You're rendering a post template and want the standard date · reading time · views byline. |

## Ajouter la signature à un gabarit d'article

`PostMeta` est la façon recommandée d'afficher les vues sur un article. Il regroupe la date, le temps de lecture et le compteur de vues sur une seule ligne, de sorte que chaque gabarit n'a pas besoin de câbler chaque élément lui-même.

```jsx
import PostMeta from "../components/PostMeta";

export default function PostTemplate({ post }) {
  return (
    <article>
      <h1>{post.title}</h1>
      <PostMeta post={post} />
      {/* …post body… */}
    </article>
  );
}
```

`PostMeta` attend que l'objet post fournisse :

| Field   | Type              | Notes                                                                 |
| ------- | ----------------- | --------------------------------------------------------------------- |
| `id`    | string            | Used as the view-counter key. Required for view tracking.             |
| `date`  | string (optional) | Rendered as-is when present. Omit to hide the date segment.           |
| `body`  | string[] (optional) | Joined together and passed to the reading-time estimator.            |

Chaque segment se masque de lui-même si ses données sont absentes ou si l'appel réseau n'a pas encore abouti, si bien que la signature se dégrade proprement sur les articles sans date ou avant le chargement du compteur de vues.

## Afficher uniquement le compteur de vues

Si vous n'avez besoin que du nombre (par exemple, sur une carte de liste d'articles), utilisez `ViewCounter` directement :

```jsx
import ViewCounter from "../components/ViewCounter";

<ViewCounter postId={post.id} />
```

Il rend un `<span class="view-counter">` avec le nombre formaté via `toLocaleString()` (de sorte que `1234` s'affiche comme `1,234 views`). Tant que la requête est en attente, il renvoie `null` et n'affiche rien.

### Lire sans enregistrer une vue

Par défaut, monter `ViewCounter` enregistre une vue. Si vous voulez lire le nombre sans l'incrémenter — par exemple, sur un tableau de bord d'administration ou une page de listing — appelez `useViewCount` directement avec `increment: false` :

```jsx
import { useViewCount } from "../hooks/useViewCount";

function PostCard({ post }) {
  const count = useViewCount(post.id, { increment: false });
  return <li>{post.title} — {count?.toLocaleString() ?? "—"} views</li>;
}
```

## Afficher les vues totales du site

`SiteViews` affiche un résumé sur une ligne des lectures totales de tous les articles. Placez-le où vous voulez le nombre agrégé — un pied de page, une page « À propos », un bandeau de statistiques sur la page d'accueil :

```jsx
import SiteViews from "../components/SiteViews";

<SiteViews />
```

Il rend un `<p class="site-views">` avec un texte comme `12,480 total reads across all posts.`, ou rien pendant que la requête est en cours.

## Points de terminaison de l'API attendus par les hooks

Les hooks appellent un service de vues partagé. Si vous changez de backend, il doit exposer la même forme sur les mêmes chemins.

| Method | Endpoint                  | Used by         | Behavior                                                                                   |
| ------ | ------------------------- | --------------- | ------------------------------------------------------------------------------------------ |
| `POST` | `/views/:postId`          | `useViewCount` (default) | Records a view for `postId` and returns the new count.                              |
| `GET`  | `/views/:postId`          | `useViewCount` with `{ increment: false }` | Returns the current count for `postId` without incrementing.        |
| `GET`  | `/views/total`            | `useTotalViews` | Returns the aggregate read count across every post.                                        |

Les corps de réponse utilisent ces formes :

```json
// /views/:postId
{ "count": 1234 }

// /views/total
{ "total": 12480 }
```

Les deux hooks traitent les réponses différentes de `200` et les charges utiles non numériques comme des données manquantes — ils gardent l'état à `null` pour que les composants n'affichent rien plutôt que d'exposer un nombre cassé. L'URL de base est configurée dans les hooks comme `https://api.paaatrrrick.com/views`.

## Style

`PostMeta` fournit `postMeta.css`, qui dispose les segments en ligne flex avec de fins séparateurs en points entre eux. Les classes individuelles que vous pouvez cibler sont :

- `.post-meta` — la ligne englobante.
- `.post-meta-date` — le segment de date.
- `.view-counter` — le span du compteur de vues (également rendu par `ViewCounter` seul).
- `.site-views` — le paragraphe de vues totales rendu par `SiteViews`.
