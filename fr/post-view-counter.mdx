## Vue d'ensemble

Le site personnel embarque une petite suite de composants et de hooks pour suivre et afficher combien de fois les articles ont été lus :

- **`ViewCounter`** : affiche le nombre de lectures d'un article donné, appuyé par le hook `useViewCount`.
- **`SiteViews`** : affiche le nombre total de lectures sur l'ensemble des articles, appuyé par le hook `useTotalViews`.
- **`PostMeta`** : la signature combinée affichée sous le titre d'un article (date, temps de lecture estimé, nombre de vues).

Les trois s'adressent à un service de vues partagé à l'adresse `https://api.paaatrrrick.com/views`. Le service renvoie des données tolérantes au `null`, si bien que chaque composant n'affiche rien pendant que l'appel réseau est en cours ou si la requête échoue.

## Quand utiliser chaque élément

| Composant / hook         | Utilisez-le quand…                                                              |
| ------------------------ | ------------------------------------------------------------------------------- |
| `ViewCounter` / `useViewCount` | Vous voulez le nombre de lectures d'un seul article, et vous voulez que la visite soit enregistrée. |
| `SiteViews` / `useTotalViews`  | Vous voulez le nombre total de lectures sur l'ensemble du site (par exemple, pied de page, page à propos). |
| `PostMeta`               | Vous affichez un modèle d'article et voulez la signature standard date · temps de lecture · vues. |

## Ajouter la signature à un modèle d'article

`PostMeta` est la méthode recommandée pour faire apparaître les vues sur un article. Il regroupe la date, le temps de lecture et le compteur de vues sur une seule ligne, ce qui évite à chaque modèle de câbler chaque élément individuellement.

```jsx
import PostMeta from "../components/PostMeta";

export default function PostTemplate({ post }) {
  return (
    <article>
      <h1>{post.title}</h1>
      <PostMeta post={post} />
      {/* …post body… */}
    </article>
  );
}
```

`PostMeta` attend que l'objet post fournisse :

| Champ   | Type              | Notes                                                                 |
| ------- | ----------------- | --------------------------------------------------------------------- |
| `id`    | string            | Utilisé comme clé du compteur de vues. Requis pour le suivi des vues. |
| `date`  | string (optionnel) | Affiché tel quel lorsqu'il est présent. Omettez-le pour masquer la date. |
| `body`  | string[] (optionnel) | Concaténé, puis passé à l'estimateur de temps de lecture. |

Chaque segment se masque lui-même si ses données sont absentes ou si l'appel réseau n'a pas encore abouti, de sorte que la signature se dégrade gracieusement sur les articles sans date ou avant le chargement du nombre de vues.

## Afficher uniquement le nombre de vues

Si vous n'avez besoin que du compteur (par exemple sur une carte de liste d'articles), utilisez `ViewCounter` directement :

```jsx
import ViewCounter from "../components/ViewCounter";

<ViewCounter postId={post.id} />
```

Il rend un `<span class="view-counter">` avec le compteur formaté via `toLocaleString()` (ainsi `1234` s'affiche comme `1,234 views`). Pendant que la requête est en attente, il retourne `null` et n'affiche rien.

### Lire sans enregistrer une vue

Par défaut, monter `ViewCounter` enregistre une vue. Si vous voulez lire le compteur sans l'incrémenter, par exemple sur un tableau de bord d'administration ou une page de liste, appelez `useViewCount` directement avec `increment: false` :

```jsx
import { useViewCount } from "../hooks/useViewCount";

function PostCard({ post }) {
  const count = useViewCount(post.id, { increment: false });
  return <li>{post.title} — {count?.toLocaleString() ?? "—"} views</li>;
}
```

## Afficher le total des vues du site

`SiteViews` affiche un récapitulatif d'une ligne des lectures totales sur l'ensemble des articles. Placez-le partout où vous voulez le nombre global : un pied de page, une page à propos, une barre de statistiques en page d'accueil :

```jsx
import SiteViews from "../components/SiteViews";

<SiteViews />
```

Il rend un `<p class="site-views">` avec un texte du type `12,480 total reads across all posts.`, ou rien pendant que la requête est en cours.

## Endpoints API attendus par les hooks

Les hooks appellent un service de vues partagé. Si vous changez de backend, il doit exposer la même forme sur les mêmes chemins.

| Méthode | Endpoint                  | Utilisé par         | Comportement                                                                                   |
| ------- | ------------------------- | ------------------- | ---------------------------------------------------------------------------------------------- |
| `POST`  | `/views/:postId`          | `useViewCount` (par défaut) | Enregistre une vue pour `postId` et renvoie le nouveau compteur.                        |
| `GET`   | `/views/:postId`          | `useViewCount` avec `{ increment: false }` | Renvoie le compteur actuel pour `postId` sans l'incrémenter. |
| `GET`   | `/views/total`            | `useTotalViews`     | Renvoie le nombre total de lectures sur l'ensemble des articles.                               |

Les corps de réponse utilisent ces formes :

```json
// /views/:postId
{ "count": 1234 }

// /views/total
{ "total": 12480 }
```

Les deux hooks traitent les réponses non `200` et les payloads non numériques comme des données manquantes. Ils gardent l'état à `null` afin que les composants n'affichent rien plutôt qu'un nombre cassé. L'URL de base est configurée dans les hooks comme `https://api.paaatrrrick.com/views`.

## Style

`PostMeta` est fourni avec `postMeta.css`, qui dispose les segments en ligne flex avec de fins séparateurs en points entre eux. Les classes individuelles que vous pouvez cibler sont :

- `.post-meta` : la ligne englobante.
- `.post-meta-date` : le segment de la date.
- `.view-counter` : le span du compteur de vues (également rendu par `ViewCounter` seul).
- `.site-views` : le paragraphe du total des vues rendu par `SiteViews`.
