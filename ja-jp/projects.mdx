## 概要 {#overview}

個人ウェブサイトに、サイドの案件をレスポンシブなグリッドで紹介する専用の `/projects` ページが追加されました。各カードには、案件名、1 行のキャッチコピー、詳しい説明、付箋として表示される技術スタック、リポジトリまたは公開サイトへのリンクが表示されます。

エントリは `src/constants/projects.js` の `projects` 配列から読み込まれ、`/projects` ルートで `Projects` コンポーネントによってレンダリングされます。このページはホームページと並んで配置されているため、訪問者はランディングページをスクロールしなくても案件の一覧全体を閲覧できます。

## このページを使用する場面 {#when-to-use-this-page}

キャッチコピーと技術付箋を付けて、サイドの案件を独自のカードで紹介したい場合は、`/projects` にエントリを追加します。目立つ位置で紹介したい案件にはホームページの一覧を使用し、完全なカタログには `/projects` を使用してください。

## エントリのスキーマ {#entry-schema}

`projects` 配列内の各オブジェクトは、次のフィールドをサポートしています。オプションと記載されているもの以外、すべてのフィールドが必須です。

| フィールド    | 型       | 説明                                                                                         |
| ------------- | -------- | -------------------------------------------------------------------------------------------- |
| `name`        | string   | カードの見出しとリンクテキストとして表示される案件名。                                       |
| `tagline`     | string   | 名前のすぐ下に表示される 1 行の概要。                                                        |
| `description` | string   | 案件の内容と対象者を説明する、より長い段落。                                                 |
| `tech`        | string[] | 横並びのリストとして表示されるスタックの付箋（例: `['React', 'Rust', 'SQLite']`）。          |
| `status`      | string   | 案件のライフサイクル。現在もメンテナンスしている案件には `'Active'` を、更新を提供しなくなった案件には `'Archived'` を使用します。カードのヘッダーに色付きのバッジとして表示されます。 |
| `link`        | string   | カードの見出しのリンク先 URL。新しいタブで開きます。リポジトリまたは公開サイトを使用します。 |
| `repo`        | string   | オプション。リポジトリの URL。設定すると、カードの技術リストの横に **ソースコード** リンクが表示されます。新しいタブで開きます。 |

## 案件の追加 {#adding-a-project}

`src/constants/projects.js` を開き、`projects` 配列に新しいオブジェクトを追加します。エントリは配列の順序でレンダリングされるため、最新または最も関連性の高い案件を先頭に置いてください。

```js src/constants/projects.js
const projects = [
    {
        name: 'Inkwell',
        tagline: 'A markdown-first note-taking app',
        description: 'A local-first notes app with bidirectional links, a command palette, and end-to-end encrypted sync.',
        status: 'Active',
        tech: ['React', 'Rust', 'SQLite'],
        link: 'https://inkwell.example.com',
        repo: 'https://github.com/example/inkwell',
    },
];

export default projects;
```

<Tip>
`tagline` は、モバイルで 1 行に収まる程度の短さにしてください。60 文字未満を目安にします。より長い説明は `description` に記載しましょう。
</Tip>

## 執筆のガイダンス {#writing-guidance}

`/projects` ページには、`name`、`tagline`、`description` を対象に照合する検索ボックスがあり、技術フィルターと組み合わせて使用できます。案件が検索で見つかるように、これら 3 つのフィールドには、訪問者が実際に入力しそうな言葉（製品カテゴリ、課題領域、まだ付箋になっていないスタックのキーワードなど）を使って記述してください。

- **名前:** 案件の正式名称を使用します。絵文字の接頭辞は使わないでください。カードのデザインは整った文字の階層構造を前提としています。
- **キャッチコピー:** カテゴリや中核となる仕組みから書き始めます（「A project I built」ではなく「Self-hosted bookmark manager」など）。
- **説明:** 1〜2 文で記述します。何をするものか、対象者やユースケースについて触れてください。
- **技術付箋:** すべての依存関係ではなく、スタックの中核となる要素を挙げます。3〜5 個の付箋が最も読みやすくなります。
- **ステータス:** 現在もメンテナンスしている案件には `'Active'` を設定します。更新の提供をやめたら `'Archived'` に切り替えて、案件が凍結されていることを訪問者に知らせます。バッジは緑からグレーに変わります。
- **リンク:** オープンソースの成果物にはリポジトリの URL を、ホスティングされた案件には公開サイトを優先してください。オープンソースでもあるホスティングされた案件の場合は、`link` を公開サイトに向け、`repo` にリポジトリの URL を設定します。

## ナビゲーション {#navigation}

このページは `src/App.js` で次のように設定されています。

```js src/App.js
<Route exact path='/projects' component={Projects} />
```

サイト内のどこからでも `/projects` でリンクできます。このページのヘッダーには、ルートに直接アクセスした訪問者向けに「← Back home」リンクが含まれています。
