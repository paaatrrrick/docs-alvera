## 概要 {#overview}

個人ウェブサイトに、サイド案件をレスポンシブなグリッドで紹介する専用の `/projects` ページが追加されました。各カードには、案件名、1 行のキャッチコピー、詳しい説明、付箋として表示される技術スタック、リポジトリまたは公開中のサイトへのリンクが表示されます。

エントリーは `src/constants/projects.js` の `projects` 配列から読み込まれ、`/projects` ルートで `Projects` コンポーネントによってレンダリングされます。このページはホームページと並んで配置されているため、訪問者はランディングページをスクロールしなくても案件の一覧全体を閲覧できます。

## このページを使うタイミング {#when-to-use-this-page}

サイド案件をキャッチコピーと技術付箋付きの専用カードで紹介したい場合は、`/projects` にエントリーを追加します。目立たせたい案件にはホームページのリストを使い、すべての案件をまとめたカタログには `/projects` を使います。

## エントリーのスキーマ {#entry-schema}

`projects` 配列の各オブジェクトは、次のフィールドに対応しています。オプションと記載されているもの以外、すべてのフィールドが必須です。

| フィールド    | 型       | 説明                                                                                         |
| ------------- | -------- | -------------------------------------------------------------------------------------------- |
| `name`        | string   | カードの見出しおよびリンクテキストとして表示される案件名。                                   |
| `tagline`     | string   | 名前のすぐ下に表示される 1 行の要約。                                                        |
| `description` | string   | 案件の内容と対象ユーザーを説明する、より長い段落。                                           |
| `tech`        | string[] | 横並びのリストとして表示されるスタックの付箋 (例: `['React', 'Rust', 'SQLite']`)。           |
| `status`      | string   | 案件のライフサイクル。現在もメンテナンスしている案件には `'Active'`、更新を終了した案件には `'Archived'` を使用します。カードのヘッダーに色付きのバッジとして表示されます。 |
| `link`        | string   | カードの見出しのリンク先 URL。新しいタブで開きます。リポジトリまたは公開中のサイトを指定します。 |
| `repo`        | string   | オプション。リポジトリの URL。設定すると、カードの技術リストの横に **Source code** リンクが表示されます。新しいタブで開きます。 |

## 案件を追加する {#adding-a-project}

`src/constants/projects.js` を開き、`projects` 配列に新しいオブジェクトを追加します。エントリーは配列の順に表示されるため、最新または最も重要な案件を先頭に置いてください。

```js src/constants/projects.js
const projects = [
    {
        name: 'Inkwell',
        tagline: 'A markdown-first note-taking app',
        description: 'A local-first notes app with bidirectional links, a command palette, and end-to-end encrypted sync.',
        status: 'Active',
        tech: ['React', 'Rust', 'SQLite'],
        link: 'https://inkwell.example.com',
        repo: 'https://github.com/example/inkwell',
    },
];

export default projects;
```

<Tip>
`tagline` は、モバイルで 1 行に収まるよう短くしてください。目安は 60 文字未満です。詳しい紹介文は `description` に記載します。
</Tip>

## 執筆のガイドライン {#writing-guidance}

`/projects` ページには、`name`、`tagline`、`description` を対象とする検索ボックスがあり、技術フィルターと組み合わせて使えます。案件が検索で見つかるように、これら 3 つのフィールドには訪問者が実際に入力しそうな言葉を使ってください。たとえば、製品カテゴリー、課題の領域、付箋になっていないスタックのキーワードなどです。

- **名前:** 案件の正式名称を使用します。絵文字の接頭辞は付けないでください。カードのデザインは整った文字の階層構造を前提としています。
- **キャッチコピー:** カテゴリーまたは中心となる仕組みから書き始めます (「A project I built」ではなく「Self-hosted bookmark manager」のように)。
- **説明:** 1〜2 文で記述します。何ができるのか、対象ユーザーやユースケースを記載します。
- **技術付箋:** すべての依存関係ではなく、スタックの中核となる要素を挙げます。3〜5 個の付箋が最も読みやすくなります。
- **ステータス:** 現在もメンテナンスしている案件には `'Active'` を設定します。更新を終了したら `'Archived'` に切り替えて、案件が凍結されていることを訪問者に伝えます。バッジは緑からグレーに変わります。
- **リンク:** オープンソースの案件にはリポジトリの URL、ホスティングされている案件には公開中のサイトを優先して指定します。ホスティングされていてオープンソースでもある案件では、`link` に公開中のサイトを指定し、`repo` にリポジトリの URL を設定します。

## ナビゲーション {#navigation}

このページは `src/App.js` で次のように設定されています。

```js src/App.js
<Route exact path='/projects' component={Projects} />
```

サイト内のどこからでも `/projects` でこのページにリンクできます。このページのヘッダーには、ルートに直接アクセスした訪問者向けに「← Back home」リンクがあります。
