## 概要 {#overview}

個人ウェブサイトに、サイド案件をレスポンシブなグリッドで紹介する専用の `/projects` ページが追加されました。各カードには、案件名、1 行のキャッチコピー、詳しい説明、付箋として表示される技術スタック、リポジトリまたは公開サイトへのリンクが表示されます。

エントリーは `src/constants/projects.js` の `projects` 配列から取得され、`/projects` ルートで `Projects` コンポーネントによってレンダリングされます。このページはホームページと並んで配置されているため、訪問者はランディングページをスクロールしなくても案件の一覧全体を閲覧できます。

## このページを使用する場面 {#when-to-use-this-page}

サイド案件を、キャッチコピーと技術付箋付きの専用カードで紹介したい場合は、`/projects` にエントリーを追加します。目立つ位置で紹介したい案件にはホームページの一覧を使用し、すべての案件を網羅したカタログには `/projects` を使用します。

## エントリーのスキーマ {#entry-schema}

`projects` 配列内の各オブジェクトは、次のフィールドをサポートします。任意と記載されているもの以外、すべてのフィールドは必須です。

| フィールド    | 型       | 説明                                                                                         |
| ------------- | -------- | -------------------------------------------------------------------------------------------- |
| `name`        | string   | カードの見出しおよびリンクテキストとしてレンダリングされる案件名。                           |
| `tagline`     | string   | 名前のすぐ下に表示される 1 行の概要。                                                        |
| `description` | string   | 案件の内容と対象ユーザーを説明する、より長い段落。                                           |
| `tech`        | string[] | 横並びのリストとしてレンダリングされるスタック付箋（例: `['React', 'Rust', 'SQLite']`）。    |
| `status`      | string   | 案件のライフサイクル。現在もメンテナンスしている案件には `'Active'` を、今後更新を行わない案件には `'Archived'` を使用します。カードヘッダーに色付きのバッジとしてレンダリングされます。 |
| `link`        | string   | カードの見出しのリンク先 URL。新しいタブで開きます。リポジトリまたは公開サイトを使用します。 |
| `repo`        | string   | 任意。リポジトリの URL。設定すると、カードの技術リストの横に **Source code** リンクが表示されます。新しいタブで開きます。 |

## 案件を追加する {#adding-a-project}

`src/constants/projects.js` を開き、`projects` 配列に新しいオブジェクトを追加します。エントリーは配列の順序でレンダリングされるため、最新または最も関連性の高い案件を先頭に置いてください。

```js src/constants/projects.js
const projects = [
    {
        name: 'Inkwell',
        tagline: 'A markdown-first note-taking app',
        description: 'A local-first notes app with bidirectional links, a command palette, and end-to-end encrypted sync.',
        status: 'Active',
        tech: ['React', 'Rust', 'SQLite'],
        link: 'https://inkwell.example.com',
        repo: 'https://github.com/example/inkwell',
    },
];

export default projects;
```

<Tip>
`tagline` は、モバイルで 1 行に収まるよう短くしてください。60 文字未満を目安にします。詳しい紹介文は `description` に記載しましょう。
</Tip>

## 記述のガイドライン {#writing-guidance}

`/projects` ページには、`name`、`tagline`、`description` を対象に照合する検索ボックスがあり、技術フィルターと組み合わせて使用されます。案件が検索で見つかるよう、これら 3 つのフィールドには、訪問者が実際に入力するであろう言葉（製品カテゴリー、課題領域、付箋にまだ含まれていないスタックのキーワードなど）を使って記述してください。

- **名前:** 案件の正式名称を使用します。絵文字の接頭辞は付けないでください。カードのデザインは、すっきりとした文字の階層構造を前提としています。
- **キャッチコピー:** カテゴリーや中心となる仕組みから書き始めます（「A project I built」ではなく「Self-hosted bookmark manager」のように）。
- **説明:** 1〜2 文で記述します。何をするものか、そして対象ユーザーやユースケースに触れます。
- **技術付箋:** すべての依存関係ではなく、スタックの中核となる要素を挙げます。付箋は 3〜5 個が最も読みやすくなります。
- **ステータス:** 現在もメンテナンスしている案件には `'Active'` を設定します。更新の提供を停止したら `'Archived'` に切り替えて、案件が凍結されていることを訪問者に伝えます。バッジは緑からグレーに変わります。
- **リンク:** オープンソースの成果物にはリポジトリの URL を、ホスティングされている案件には公開サイトを優先します。ホスティングされていてオープンソースでもある案件の場合は、`link` に公開サイトを指定し、`repo` にリポジトリの URL を設定します。

## ナビゲーション {#navigation}

このページは `src/App.js` で次のように設定されています。

```js src/App.js
<Route exact path='/projects' component={Projects} />
```

サイト内のどこからでも `/projects` でリンクできます。このルートに直接アクセスした訪問者のために、ページのヘッダーには「← Back home」リンクがあります。
