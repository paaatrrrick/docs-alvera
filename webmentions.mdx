## Overview

[Webmention](https://www.w3.org/TR/webmention/) is a web standard that lets another site tell yours when it links to one of your posts 🔗. With Webmentions turned on, your personal website advertises an endpoint that receives these notifications and fetches the mentions for each post, grouped into likes, reposts, replies and mentions.

## Turn it on

Webmentions ship turned off. To enable them, set the `REACT_APP_WEBMENTIONS` environment variable to `on` when you build the site:

```bash .env
REACT_APP_WEBMENTIONS=on
```

Any other value, or leaving the variable unset, keeps Webmentions off. Because Create React App reads `REACT_APP_` variables at build time, rebuild and redeploy the site after you change it.

## Set your endpoint

Other sites find where to send mentions through a `<link rel="webmention">` tag in the `<head>` of every page. The tag points at the URL in `REACT_APP_WEBMENTION_ENDPOINT`:

```bash .env
REACT_APP_WEBMENTION_ENDPOINT=https://webmention.io/patrickfoster.dev/webmention
```

The site expects a [webmention.io](https://webmention.io) endpoint, because it reads mentions back from the webmention.io API. Sign in to webmention.io with your domain to get your endpoint URL, then set it here.

The tag is part of the page template, so every page advertises the endpoint even while `REACT_APP_WEBMENTIONS` is off. Other sites can start sending mentions before you show them.

## Webmentions section

When `REACT_APP_WEBMENTIONS` is `on`, a post can show a Webmentions section with the reactions it got from other sites 💬. The section shows:

1. One line with the like and repost counts, for example **3 likes · 1 reposts**.
2. A numbered list of replies. Each reply shows the author's name, linked to the reply on the other site, then a colon and the reply text.

Mentions that are not likes, reposts or replies are not shown in the section.

The section stays hidden while the mentions load. If webmention.io returns an error or can't be reached, the section stays hidden and the rest of the page loads normally.

<Note>
The section isn't added to blog post pages yet. Adding it to posts is planned for a later part of the launch.
</Note>

## Fetch mentions for a post

`fetchMentions(postUrl)` loads the mentions for one post from the webmention.io API and returns them grouped by type. It fetches up to 100 mentions per post.

```js
import { fetchMentions } from '../webmentions/fetchMentions';

const mentions = await fetchMentions('https://patrickfoster.dev/blog/my-post');

console.log(`${mentions.like.length} likes, ${mentions.reply.length} replies`);
```

Each mention is sorted into one of four groups, based on how the other site linked to your post:

| Group     | The other site's post                      |
| --------- | ------------------------------------------ |
| `like`    | Likes your post (`like-of`).               |
| `repost`  | Reposts your post (`repost-of`).           |
| `reply`   | Replies to your post (`in-reply-to`).      |
| `mention` | Links to your post in any other way.       |

All four groups are always present, as empty arrays when a post has no mentions of that type. Each mention has these fields:

| Field       | Description                                                    |
| ----------- | -------------------------------------------------------------- |
| `author`    | Name of the author. `Someone` when the mention has no author name. |
| `url`       | Link to the post that mentioned yours.                         |
| `published` | When that post was published.                                  |
| `text`      | Text of the mention. An empty string when there is none.       |

If the webmention.io API responds with an error, `fetchMentions` throws an error with the message `Webmentions unavailable (<status>)`, for example `Webmentions unavailable (503)`.
