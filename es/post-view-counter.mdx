## Descripción general

El sitio web personal incluye un pequeño conjunto de componentes y hooks para realizar el seguimiento y mostrar cuántas veces se han leído las publicaciones:

- **`ViewCounter`** — muestra el número de lecturas de una única publicación, respaldado por el hook `useViewCount`.
- **`SiteViews`** — muestra el número total de lecturas en todas las publicaciones, respaldado por el hook `useTotalViews`.
- **`PostMeta`** — la firma combinada que aparece bajo el título de una publicación (fecha, tiempo de lectura estimado y contador de vistas).

Los tres consultan un servicio de vistas compartido en `https://api.paaatrrrick.com/views`. El servicio devuelve datos seguros frente a `null`, por lo que cada componente no renderiza nada mientras la llamada de red está en curso o si la solicitud falla.

## Cuándo usar cada pieza

| Component / hook         | Use when…                                                                       |
| ------------------------ | ------------------------------------------------------------------------------- |
| `ViewCounter` / `useViewCount` | You want a single post's read count, and you want the visit to be recorded.    |
| `SiteViews` / `useTotalViews`  | You want the total-reads number across the whole site (e.g. footer, about page). |
| `PostMeta`               | You're rendering a post template and want the standard date · reading time · views byline. |

## Añadir la firma a una plantilla de publicación

`PostMeta` es la forma recomendada de mostrar el número de vistas en una publicación. Combina la fecha, el tiempo de lectura y el contador de vistas en una sola línea, para que cada plantilla no tenga que conectar cada pieza por sí misma.

```jsx
import PostMeta from "../components/PostMeta";

export default function PostTemplate({ post }) {
  return (
    <article>
      <h1>{post.title}</h1>
      <PostMeta post={post} />
      {/* …post body… */}
    </article>
  );
}
```

`PostMeta` espera que el objeto post proporcione:

| Field   | Type              | Notes                                                                 |
| ------- | ----------------- | --------------------------------------------------------------------- |
| `id`    | string            | Used as the view-counter key. Required for view tracking.             |
| `date`  | string (optional) | Rendered as-is when present. Omit to hide the date segment.           |
| `body`  | string[] (optional) | Joined together and passed to the reading-time estimator.            |

Cada segmento se oculta si faltan sus datos o si la llamada de red aún no se ha resuelto, por lo que la firma se degrada con elegancia en publicaciones sin fecha o antes de que se cargue el contador de vistas.

## Mostrar solo el número de vistas

Si solo necesitas el número (por ejemplo, en una tarjeta de listado de publicaciones), usa `ViewCounter` directamente:

```jsx
import ViewCounter from "../components/ViewCounter";

<ViewCounter postId={post.id} />
```

Renderiza un `<span class="view-counter">` con el número formateado mediante `toLocaleString()` (de modo que `1234` se muestra como `1,234 views`). Mientras la solicitud está pendiente, devuelve `null` y no renderiza nada.

### Leer sin registrar una vista

De forma predeterminada, montar `ViewCounter` registra una vista. Si quieres leer el número sin incrementarlo — por ejemplo, en un panel de administración o en una página de listado — llama a `useViewCount` directamente con `increment: false`:

```jsx
import { useViewCount } from "../hooks/useViewCount";

function PostCard({ post }) {
  const count = useViewCount(post.id, { increment: false });
  return <li>{post.title} — {count?.toLocaleString() ?? "—"} views</li>;
}
```

## Mostrar el total de vistas del sitio

`SiteViews` renderiza un resumen de una sola línea con las lecturas totales de todas las publicaciones. Colócalo en cualquier lugar donde quieras mostrar la cifra agregada: un pie de página, una página «Acerca de» o una franja de estadísticas en la página de inicio:

```jsx
import SiteViews from "../components/SiteViews";

<SiteViews />
```

Renderiza un `<p class="site-views">` con un texto como `12,480 total reads across all posts.`, o nada mientras la solicitud está en curso.

## Puntos de conexión de la API que esperan los hooks

Los hooks llaman a un servicio de vistas compartido. Si cambias el backend, debe exponer la misma forma en las mismas rutas.

| Method | Endpoint                  | Used by         | Behavior                                                                                   |
| ------ | ------------------------- | --------------- | ------------------------------------------------------------------------------------------ |
| `POST` | `/views/:postId`          | `useViewCount` (default) | Records a view for `postId` and returns the new count.                              |
| `GET`  | `/views/:postId`          | `useViewCount` with `{ increment: false }` | Returns the current count for `postId` without incrementing.        |
| `GET`  | `/views/total`            | `useTotalViews` | Returns the aggregate read count across every post.                                        |

Los cuerpos de respuesta tienen estas formas:

```json
// /views/:postId
{ "count": 1234 }

// /views/total
{ "total": 12480 }
```

Ambos hooks tratan las respuestas distintas de `200` y los cuerpos no numéricos como datos ausentes: mantienen el estado en `null` para que los componentes no rendericen nada en lugar de mostrar un número roto. La URL base está configurada en los hooks como `https://api.paaatrrrick.com/views`.

## Estilos

`PostMeta` incluye `postMeta.css`, que dispone los segmentos como una fila flex con finos separadores de puntos entre ellos. Las clases individuales a las que puedes apuntar son:

- `.post-meta` — la fila que las envuelve.
- `.post-meta-date` — el segmento de fecha.
- `.view-counter` — el span del contador de vistas (también lo renderiza `ViewCounter` por sí solo).
- `.site-views` — el párrafo de vistas totales renderizado por `SiteViews`.
