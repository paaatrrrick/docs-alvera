When a list endpoint returns many results, the API paginates them so responses stay small and fast. Use the `next_cursor` field to fetch each subsequent page, and the `limit` query parameter to control how many items you receive per page.

## Cursor pagination

Most of our list endpoints use cursor pagination. Each response includes a `next_cursor`, which you pass back to get the next page.

```bash
curl "https://api.example.dev/items?limit=50&cursor=abc123"
```

Keep requesting until `next_cursor` comes back null. That means you reached the end. The [API reference](/api-reference/introduction) documents this for every endpoint.

## Page size

You can control how many items per page with the `limit` param. The max is 100. If you ask for more, the API caps the result at 100. For very large exports, use [the export API](#the-bulk-export) instead, since it is more efficient.

See also [the pagination examples](https://api.example-broken.dev/pagination-examples) for code in several languages.
