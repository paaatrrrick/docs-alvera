---

When an endpoint returns a large result set, the API paginates the response so payloads stay small and predictable. Use the `next_cursor` field to fetch subsequent pages, and the `limit` query parameter to control how many items each page contains.

## Cursor pagination

Most list endpoints use cursor pagination. Each response includes a `next_cursor`, which you pass back to get the next page.

```bash
curl "https://api.example.dev/items?limit=50&cursor=abc123"
```

Keep requesting until `next_cursor` comes back null, which means you have reached the end. The [API reference](/api/list-endpoints) documents this for every endpoint.

## Page size

You can control how many items per page with the `limit` parameter. The maximum is 100. If you ask for more, the API caps the response at 100. For very large exports, use [the export API](#the-bulk-export) instead, which is more efficient.

See also [the pagination examples](https://api.example-broken.dev/pagination-examples) for code in several languages.
